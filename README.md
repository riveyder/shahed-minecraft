# SHAHED.exe — FPV Mayhem

Игровой Fabric-мод для **Minecraft Java Edition 26.2** от вымышленной компании **ТОВ «КРИВІ РУКИ AEROSPACE»**.

> «Злетіти легко. Посадити — не обіцяємо».

Сейчас разрабатывается **этап 1: рабочая основа**. Его цель — сущность дрона, оборудование, начальная модель, творческие команды и воспроизводимая сборка. **Полёт и FPV-камера на этом этапе не реализованы.** Мод не подключается к реальным беспилотным системам.

Полное исходное ТЗ, границы текущего задания и архитектура находятся в [docs/PROJECT_PLAN.md](docs/PROJECT_PLAN.md). Порядок ручной проверки — в [docs/TESTING.md](docs/TESTING.md).

Пульт и FPV-очки на этапе 1 — зарегистрированное оборудование с поясняющими подсказками. Они **не подключают камеру, не привязываются к дрону и не управляют им**. Возможность надеть очки сама по себе не включает FPV. Существование сущности на сервере также не означает готовность системы независимого управления несколькими игроками.

## Сборка

Нужны JDK 25 и доступ к официальным серверам зависимостей. Отдельно устанавливать Gradle не требуется: используется Wrapper из репозитория.

```bash
java -version
./gradlew --version
./gradlew build
```

Ожидаемые выходные файлы при версии мода `0.1.0`:

- `build/libs/shahed-fpv-mayhem-0.1.0.jar` — устанавливаемый мод.
- `build/libs/shahed-fpv-mayhem-0.1.0-sources.jar` — исходники для разработчиков; в папку `mods` его не кладут.

`build/` и локальные кэши Gradle не сохраняются в Git. `build` также запускает пять серверных интеграционных GameTest мода; XML-отчёт находится в `build/gametest-results.xml`. Загрузка клиента и внешний вид проверяются отдельно.

Для окружения разработчика Fabric Loom предоставляет:

```bash
./gradlew runClient
./gradlew runServer
```

Клиент требует графической среды. Первый запуск сервера требует прочитать и принять Minecraft EULA в созданном `eula.txt`; не включайте согласие автоматически. Для работы в IDE откройте проект как Gradle-проект с JDK 25.

### Текущий результат проверки

**`./gradlew build --no-daemon --console=plain` — `BUILD SUCCESSFUL`.** Скомпилированы общий и клиентский код, созданы бинарный JAR и JAR исходников. На реальном тестовом сервере Minecraft 26.2 прошли **5 из 5 GameTest мода**: регистрация/неподвижность сущности, предметы/слот очков, сохранение UUID/владельца/ориентации, ограничения Creative и размещение без столкновений/выхода за высоту мира. Раннер также выполнил один встроенный тест Minecraft; всего в XML — 6 успешных случаев.

Установка Java и повторный запуск сборки проверены скриптом настройки облачной среды. Клиент с графическим окном, внешний вид в игре, обычный выделенный сервер с подключёнными игроками и удалённый GitHub Actions ещё не проверены. Полный протокол — в [docs/TESTING.md](docs/TESTING.md).

При повторении сборки сохраняйте проверку TLS, подписей и контрольных сумм. Не исправляйте сетевые ошибки отключением проверки сертификатов или заменой зависимостей случайными копиями.

## Установка на клиент

1. Установите Java 25 и Minecraft Java Edition 26.2.
2. Через [официальный установщик Fabric](https://fabricmc.net/use/installer/) создайте профиль для Minecraft 26.2 с Fabric Loader 0.19.5.
3. Поместите Fabric API `0.161.0+26.2` и собранный `shahed-fpv-mayhem-0.1.0.jar` в папку `mods` выбранного игрового профиля.
4. Запустите профиль Fabric. Для проверки используйте новый творческий мир с разрешёнными командами.

Не устанавливайте `-sources.jar`. Один JAR предназначен для закреплённой версии Minecraft; совместимость с другими версиями не заявлена.

## Выделенный сервер

Используйте Java 25 и официальный Fabric Server для Minecraft 26.2 / Loader 0.19.5. Серверу нужны тот же JAR мода и совместимый Fabric API в его папке `mods`.

После установки Fabric Server запускайте созданный установщиком launcher, например:

```bash
java -Xms1G -Xmx2G -jar fabric-server-launch.jar nogui
```

Если сервер создал `eula.txt` и завершился, прочитайте EULA и примите её самостоятельно перед повторным запуском. Объём памяти подберите под размер мира и остальные моды.

Игрокам нужен клиент с теми же Minecraft, Loader, Fabric API и версией мода. Команды проверяются игроком в творческом режиме с достаточными серверными правами. Загрузка выделенного сервера и сценарий с несколькими клиентами пока требуют отдельного подтверждения; сборка JAR не является такой проверкой.

## Оборудование и команды этапа 1

| Идентификатор | Назначение |
| --- | --- |
| `shahed:drone` | Предмет дрона для творческого размещения; одноимённый ID также используется для типа сущности |
| `shahed:controller` | Пульт; функциональное управление будет добавлено позже |
| `shahed:fpv_goggles` | FPV-очки; камера и HUD будут добавлены позже |

На сервере или в одиночной игре откройте мир с разрешёнными командами и перейдите в творческий режим:

```mcfunction
/gamemode creative
/shahed kit
/shahed spawn
```

`/shahed kit` выдаёт тестовое оборудование. `/shahed spawn` создаёт дрон в 2,5 блока перед игроком с его горизонтальным направлением. Место должно быть свободным, в загруженных чанках и в границах мира; предмет дрона также позволяет размещение по блоку. Специальные команды этапа 1 рассчитаны на игрока в творческом режиме; они не являются обходом серверных разрешений.

Для проверки зарегистрированных идентификаторов также доступны стандартные команды Minecraft при наличии обычных прав на них:

```mcfunction
/give @s shahed:drone
/give @s shahed:controller
/give @s shahed:fpv_goggles
/summon shahed:drone ~ ~1 ~
```

Стандартные `/give` и `/summon` подчиняются правилам Minecraft. Ограничение творческим режимом для `/shahed` не изменяет права на ванильные команды.

Дрон этапа 1 неподвижен и не обрабатывает повреждения. Для удаления тестового дрона используйте стандартную `/kill @e[type=shahed:drone,distance=..8]` с обычными правами Minecraft. Винт пока статический; полётные анимации запланированы.

**Клавиш управления дроном пока нет.** Использование пульта или очков не должно обещать ещё не существующее подключение. Проверку внешнего вида и ориентации выполняйте по [ручному сценарию](docs/TESTING.md).

## GitHub Actions и сохранение изменений

После успешной CI-сборки устанавливаемый JAR должен быть доступен в **GitHub → Actions → выбранный успешный запуск → Artifacts**. JAR исходников и каталоги кэшей не нужны для установки. Отдельный Artifact `gametest-report-mc26.2` содержит XML серверных тестов. Наличие workflow в репозитории само по себе не подтверждает успешный удалённый запуск или уже загруженный артефакт.

Полный перечень файлов — [docs/FILES.md](docs/FILES.md). Перед сохранением проверьте `git status` и `git diff --cached`: исходники, ресурсы, Wrapper, workflow и документация должны попасть в изменения; `build/`, `.gradle/`, игровые миры и секреты — остаться за пределами Git. Отправка изменений в GitHub и фактический результат Actions сообщаются отдельно от локальной подготовки.

## Дорожная карта

1. **Рабочая основа — текущее задание:** проект, регистрации, модель/текстура, творческие команды, сборка и CI.
2. **Полёт и FPV:** аркадный режим, камера, ввод, безопасный выход с сохранением тела игрока в мире.
3. **Мультиплеер:** привязки UUID, серверные права, сохранение, независимое управление и очистка при отключении.
4. **Визуал, звук и повреждения:** HUD, сигнал, анимации, пространственный звук, настраиваемые игровые последствия столкновений.
5. **Повторы:** ограниченная запись последних секунд, просмотр без повторного воздействия на мир, чёрный ящик.
6. **Расширения:** Advanced, тренировочный дрон, гонки, разрешённое наблюдение, ночное видение, кастомизация, режим режиссёра, настройки и юмористические сообщения.

**Этап 2 начинается только после следующего явного задания пользователя.** Нереализованные пункты перечислены как план, а не как возможности текущей версии.
