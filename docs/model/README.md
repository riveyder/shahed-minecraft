# Модель первого этапа

Модель — оригинальный условный дрон с дельтавидным крылом, созданный для Minecraft. Это набор отдельных деталей: фюзеляж, ступенчатый нос, шесть панелей крыла, киль, двигатель, ступица, две пересекающиеся лопасти заднего винта, опоры и антенна. Полётных анимаций на первом этапе нет.

`drone-model.json` — редактируемый чертёж геометрии и UV для Java-модели. Это справочный формат проекта, а не автоматически загружаемая Minecraft JSON-модель. При изменении геометрии синхронизируйте Java-модель и этот файл. Одна единица равна одному пикселю модели, 16 единиц — одному блоку.

`drone.bbmodel` — модель в формате **Blockbench Free Model**, версия формата `4.10`: 17 отдельных редактируемых кубоидов, корневая группа `drone`, UV каждой грани и встроенная PNG-текстура 128 × 128. Её можно открыть через **File → Open Model** в Blockbench. Специальный плагин не нужен. Это исходник для редактирования, а не ресурс, который Minecraft загружает вместо Java-класса.

В Blockbench используется обычная ось **+Y вверх**, поэтому координаты переведены по правилу `blockbenchY = 8 − javaLocalY`. Для куба нужно применять правило к обеим границам Y, затем упорядочить `from` и `to`. Корневая группа в редакторе имеет pivot `[0, 8, 0]`, геометрический пол находится на Y = 0. Локальный нос по-прежнему направлен на −Z. Автоматического импорта изменений из Blockbench в Java пока нет.

## Ориентация

Нос смотрит вдоль локальной **−Z**, задний винт находится на **+Z**, верх соответствует **−Y**. Корневой сдвиг Java-модели `[0, 16, 0]` и опоры высотой 6 пикселей размещают нижнюю плоскость опор на земле. Нижний конец вертикальной лопасти находится на один пиксель выше земли. Java-рендерер применяет поворот вокруг Y на `180 − entityYaw` градусов с учётом стандартного переворота осей модели. При yaw `0` нос должен смотреть вдоль мирового **+Z**. Это соглашение нужно сохранить при добавлении движения и камеры.

Внешний вид проверяется в игре: сравнить направление носа с F3 и yaw сущности при `0`, `90`, `180` и `270` градусах; проверить, что двигатель и винт остаются сзади. Сборка проверяет наличие классов и ресурсов, но сама по себе не подтверждает визуальную ориентацию.

![Предварительный вид геометрии дрона](drone-preview.png)

`drone-preview.png` построен вне игры по чертежу и PNG-атласу: текстурированный ракурс, вид сверху и вид сбоку. Он позволяет проверить ступенчатый силуэт, положение винта сзади и зазор над полом. Это проверка геометрии; запуск Minecraft и игровую камеру она не заменяет.

## Атлас `textures/entity/drone.png`

Размер — **128 × 128** пикселей. Используется стандартная развёртка `ModelPart.Cube`: для UV `[u, v]` и размеров `[x, y, z]` занята область шириной `2(x + z)` и высотой `y + z`. Парные крылья и опоры разделяют UV без зеркального флага, как в текущей Java-модели. Видимый верх после переворота Y рендерером соответствует грани с минимальным локальным Y: его прямоугольник начинается с `[u + z + x, v]`. Второй верхний прямоугольник атласа `[u + z, v]` — видимая нижняя сторона.

## Исходники изображений

Все изображения нарисованы программно специально для проекта; сторонние текстуры и модели не использованы. `generate_assets.py` воспроизводит PNG атласа, 32 × 32 пиксельные иконки трёх предметов, 128 × 128 иконку мода и JSON моделей предметов. Для запуска нужен Python 3 с Pillow:

```sh
python3 docs/model/generate_assets.py
```

Pillow нужен только автору ресурсов для регенерации и не является зависимостью сборки Gradle или запуска мода. Текстуры и JSON уже входят в исходники.

Модель Blockbench можно повторно экспортировать из чертежа стандартным Python 3 без дополнительных пакетов:

```sh
python3 docs/model/export_model.py
```

Для повторного построения PNG-предпросмотра нужны Pillow, NumPy и Matplotlib:

```sh
MPLCONFIGDIR=/tmp/shahed-matplotlib python3 docs/model/export_model.py --preview
```

Экспорт не меняет Java-код и игровые ресурсы. При создании предпросмотра он также проверяет непрозрачность всех использованных UV-пикселей на всех 102 гранях 17 кубоидов.

Локализации `en_us`, `uk_ua` и `ru_ru` содержат видимые строки первого этапа и зарезервированные ключи `message.shahed.future.*`. Последние пока нигде не показываются и не означают, что соответствующие режимы уже реализованы.
